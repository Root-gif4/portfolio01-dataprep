# 03 詳細設計書

## 1. 共通の決まりごと

- CSV はすべて **文字として** 読む（`0012` が `12` に、`1e3` が数値に化けないように）。型の判定は検証で行う
- **行番号** は CSV ファイル上の行（見出し＝1 行目、最初のデータ＝2 行目）。空行や引用符内の改行があっても、元のファイルで探せる番号にする
- 整形は「直せる範囲で直す」だけ。直せない値はそのまま残し、検証でエラーにする（整形が勝手にデータを消さない）
- 金額などの比較・合計は `Decimal` で行い、小数の誤差を出さない
- 入力ファイルは書き換えない

## 2. 読み込み（fileio.py）

| 項目 | 仕様 |
| --- | --- |
| 文字コード | `auto`：BOM → UTF-8 として読めるか → Shift_JIS（cp932）の順に試す。どれでも読めなければ中止 |
| 上限 | 200MB を超えるファイルは中止 |
| バイナリ | NUL 文字を含むファイルは中止 |
| 見出し | 前後の空白を取る。空欄の見出し・同じ名前の見出しがあれば中止 |
| 空行 | 読み飛ばし、件数を数える |
| 列数違い | 足りない列は空欄で補い、多い列は捨てる。「列の数」エラーを記録 |

書き出し：BOM 付き UTF-8、改行 CRLF。先頭が `= + - @ タブ 改行` の値は先頭に `'` を付ける（数字の `-500` などは除く）。

## 3. 設定ファイル（profiles/*.json）

```json
{
  "name": "設定の名前（必須）",
  "description": "説明",
  "encoding": "auto | utf-8 | shift_jis",
  "delimiter": ",（\\t でタブ）",
  "keys": ["重複を判定する列"],
  "allow_extra_columns": true,
  "columns": [ 列の設定 ],
  "row_rules": [ 行のルール ],
  "aggregations": [ 集計 ],
  "reconcile": { 照合 }
}
```

### 3.1 列の設定（columns）

| キー | 内容 | 既定 |
| --- | --- | --- |
| name | 列名（CSV の見出しと同じ） | 必須 |
| type | string / int / decimal / date / email / phone / code | string |
| required | 空欄をエラーにする | false |
| pattern | 正規表現（値全体が一致すること） | なし |
| min / max | 最小・最大（int・decimal だけ） | なし |
| max_length | 最大文字数 | なし |
| allowed | 使える値の一覧 | なし |
| nfkc | 全角→半角の正規化をするか | string 以外は true |
| upper | 大文字にそろえる | false |

### 3.2 型ごとの整形と検証

| type | 整形 | 検証（空欄以外） |
| --- | --- | --- |
| string | 前後の空白（全角含む）を取る | なし |
| code | NFKC・ダッシュ類→`-`・（upper なら大文字） | なし（pattern で決める） |
| int | NFKC・`,` `円` `¥` 空白を除去・`▲` `△` → `-` | `^-?\d+$` |
| decimal | int と同じ | `^-?\d+(\.\d+)?$` |
| date | `2026/1/5` `2026-1-5` `2026.1.5` `2026年1月5日` `20260105`（時刻付き可）→ `2026-01-05`。ありえない日付は直さない | `YYYY-MM-DD` かつ実在する日付 |
| email | NFKC・小文字 | `xxx@xxx.xx` の形 |
| phone | NFKC・ダッシュ類→`-`・空白除去 | 0 から始まる 10〜11 桁（ハイフン可）、または `+国番号` |

型が正しい値にだけ、min / max / max_length / pattern / allowed をかける（型エラーと二重に出さない）。

### 3.3 行のルール（row_rules）

コードを実行する（`eval`）方式は使わず、決まった種類だけを用意する。

| type | 書き方 | 意味 |
| --- | --- | --- |
| product_equals | `target`, `factors` | target ＝ factors の積（例：合計金額＝数量×単価） |
| compare | `left`, `op`, `right` | left op right（op は `< <= == != >= >`）。数値または日付 |

関係する列に数字でない値があるときは、その行のルールは判定しない（列のチェックで既にエラーになるため）。

### 3.4 集計（aggregations）

```json
{"name": "月別売上", "group_by": ["注文日:month"],
 "metrics": [{"func": "count", "label": "注文件数"}, {"func": "sum", "column": "合計金額", "label": "売上金額"}]}
```

- `group_by`：列名。date 型の列は `:month`（YYYY-MM）・`:year` で区切れる。値が空・日付でないときは「（不明）」
- `func`：count / sum / mean / min / max / nunique。sum・mean は int・decimal の列だけ
- 最後に「合計」行を付ける（全体に対して同じ計算）
- **エラーのない行だけ** を集計する

### 3.5 照合（reconcile）

```json
{"right_profile": "payments.json", "left_label": "受注", "right_label": "入金",
 "left_keys": ["注文番号"], "right_keys": ["注文番号"],
 "compare": [{"left": "合計金額", "right": "入金額", "tolerance": 0}]}
```

- 照合先のファイルは `right_profile` の設定で読む・整形・検証する（設定ファイルからの相対パス）
- キーが空欄の行と、キーが重複する 2 件目以降は照合から外し、件数をレポートに出す
- 照合は整形後の **全行**（エラー行も含む）で行う。入金額の誤りで「入金なし」に見えてしまうのを防ぐため
- 分類：一致／不一致／{left_label}のみ／{right_label}のみ。数値は差額（左−右）を出し、`|差| ≤ tolerance` なら一致
- 並び順：不一致 → 左のみ → 右のみ → 一致

## 4. 重複検出（duplicates.py）

- `keys` があればキー列、なければ行全体で比較（整形後の値で比べるので `ord-1` と `ORD-1` も重複になる）
- キーが空欄の行は対象外（必須チェックで見つける）
- 同じグループの最初の行を残し、2 行目以降を「重複」エラーにする。メッセージに最初の行番号を入れる

## 5. 一連の処理（pipeline.py）

```
run(RunOptions, history, progress) -> RunResult
```

| 段階 | 進み具合 |
| --- | --- |
| 設定を読む | 5% |
| 入力の 読み込み・整形・検証・重複 | 15% |
| 照合先の処理 | 45% |
| 照合 | 60% |
| 集計 | 75% |
| 書き出し | 85% |
| 完了 | 100% |

例外の扱い：

| 例外 | 画面への表示 | ログ |
| --- | --- | --- |
| ProfileError / DataFileError / ProcessingError | 理由をそのまま表示 | 警告として 1 行 |
| それ以外 | 「想定外のエラー（受付番号 run_id）」だけ | トレースバックを記録 |

どの場合も `finally` で履歴に 1 行を追記する（成功・失敗とも）。

## 6. 画面（gui/app.py）

- Tk は 1 つのスレッドからしか操作できないため、処理は別スレッドで動かし、結果は `queue.Queue` に入れて画面側が 100ms ごとに取り出す
- 表は先頭 1,000 行まで表示（すべては CSV で見る）。列の幅は見出しと先頭 60 行の文字幅から決める
- Windows の高解像度画面でぼやけないよう DPI 対応を宣言する
- 「レポートを開く」「出力フォルダを開く」は Windows では `os.startfile` でファイル・フォルダそのものを開く（`file:///` の URL を渡すと、日本語のパスで Edge の空のページが開くことがあるため）
- カードとグラフは追加のライブラリを使わず `tk.Canvas` で描く（`gui/charts.py`）。大きさが変わるたびに描き直し、文字の位置はフォントの高さから計算する（画面の拡大率が違っても重ならない）
- 配色は `gui/theme.py` にダーク・ライトの 2 組を持つ。切り替えると ttk のスタイルを作り直し、自分で色を持つ部品（カード・グラフ・メニュー・表の行の色）には登録した関数で描き直してもらう
- 選んだモードは `data/settings.json` に `{"theme": "dark"}` の形で保存する。読めない・壊れているときは無視してダークで開く
- ダッシュボードの「いちばん多い・少ない」は、選んだ集計の「比べる値」が最大・最小の行（「合計」行は除く）
